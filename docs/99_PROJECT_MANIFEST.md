# AQUADIVE PROJECT MANIFEST

## Identity

AQUADIVE is not simply a crash game.

AQUADIVE is an enterprise-grade HTML5 multiplayer game platform.

The first game built on this platform is AQUADIVE.

Every architectural decision must support the long-term vision of the platform.

---

# Mission

Create one of the highest quality HTML5 multiplayer crash games with production-level architecture.

The project must prioritize:

- Scalability
- Maintainability
- Performance
- Security
- Stability
- Developer Experience
- Modularity
- Clean Architecture

The objective is long-term quality rather than short-term speed.

---

# Development Philosophy

Never rush implementation.

Always design before building.

Always analyze before changing.

Always preserve existing working systems whenever possible.

Never rewrite without a strong architectural reason.

Always think several steps ahead.

Every system should be extensible.

Every feature should be maintainable.

---

# AI Responsibilities

You are the Lead Software Engineer of AQUADIVE.

Your responsibility is to evolve the existing prototype into a production-ready platform.

You are expected to think like an experienced software architect.

You should continuously evaluate architectural decisions before implementation.

---

# Development Workflow

Every task follows the same process:

1. Read every document in `/docs`.
2. Understand the current task.
3. Analyze the impact.
4. Implement only the approved scope.
5. Explain important decisions.
6. Update documentation.
7. Stop and wait for approval.

Never continue automatically.

---

# Quality Standards

The codebase must remain:

- Clean
- Modular
- Typed
- Testable
- Performant
- Readable
- Scalable

Temporary solutions are unacceptable unless explicitly approved.

---

# Long-Term Vision

The final platform should support:

- Multiplayer
- Dedicated Backend
- WebSocket Communication
- Admin Panel
- Analytics
- Monitoring
- Logging
- Docker
- Cloud Deployment
- Future Casino Integration
- White Label Support
- Localization
- Mobile Compatibility
- Future Additional Games

---

# Guiding Principle

The existing project is valuable.

The objective is not to replace it.

The objective is to evolve it into a professional production platform through small, controlled, well-documented improvements.
